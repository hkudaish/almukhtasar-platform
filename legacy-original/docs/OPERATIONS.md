# التشغيل والنشر

## بيئة الإنتاج المقترحة

- Next.js خلف CDN/WAF، وخدمة Node/NestJS مستقلة لعقود الإدارة والجوال.
- PostgreSQL مع نسخ احتياطية يومية واستعادة زمنية، Redis/BullMQ للمهام، وMeilisearch أو OpenSearch للبحث.
- تخزين S3 مع فحص الملفات، روابط موقعة، وسياسة احتفاظ. الأسرار في Secret Manager لا في المستودع.
- بيئات منفصلة للتطوير والاختبار والإنتاج، ونشر تدريجي مع إمكانية rollback.

## قاعدة لوحة الإدارة المحلية

تستخدم النسخة التشغيلية `node:sqlite` وتخزن البيانات في `data/almukhtasar-admin.db`. تدعم واجهات الإدارة الإضافة والتعديل والأرشفة والاستعادة والبحث والترقيم والإعدادات وسجل التدقيق، وتُنشئ وحدة النسخ الاحتياطي ملفات SQLite فعلية في `data/backups/`. هذه الملفات مستبعدة من Git.

SQLite مناسب للتطوير والعرض أحادي الخادم. قبل الإنتاج متعدد النسخ يجب نقل طبقة `lib/admin-db.ts` إلى PostgreSQL/Prisma، وإضافة جلسات مصادقة موقعة وRBAC حقيقي؛ لا ينبغي نشر `/admin` أو `/api/admin` على الإنترنت قبل ذلك.

## محرك جلب الأخبار

كل تشغيل يدوي أو مجدول يمر عبر المسار نفسه:

`Source Adapter → Discovery Queue → Article Hydration Queue → Validation → Deduplication → Classification → Summary → Editorial Rules → Publication → Cache Invalidation`

- يختار محول المصدر API الرسمي، ثم RSS/Atom، ثم صفحة الأخبار، ويستخدم `renderEndpoint` الاختياري فقط للمواقع المعتمدة التي لا يظهر محتواها في HTML الأولي.
- RSS وAPI مرحلتا اكتشاف فقط؛ يُفتح رابط المقال الأصلي دائمًا لاستخراج العنوان والمتن والصورة والتاريخ والرابط القانوني.
- تحفظ `news_pipeline_queue` حالة العمل القابلة للاستئناف، وتحفظ `source_retrieval_state` مؤشرات الصحة وETag وLast-Modified وآخر رابط وتاريخ.
- تعرض `/api/admin/retrieval/health` صحة المحولات، وتظهر البيانات نفسها في لوحة الأتمتة.
- يستخدم `/api/admin/content/repair-imports` المحرك نفسه لإعادة ترطيب المواد القديمة، ولا ينشر المواد الناقصة.
- الصور الأصلية تمر عبر التحقق من MIME والأبعاد والسياق، ثم تحفظ نسخة مستقرة عند أول طلب عبر `/api/media/source-image/[id]`. صورة التصنيف المعتمدة هي البديل الوحيد عند غياب صورة أصلية صالحة.

## بوابات الإطلاق

1. استبدال بيانات `lib/data.ts` بمستودع بيانات خلف واجهة API.
2. إضافة المصادقة و2FA وRBAC قبل إتاحة `/admin`.
3. تشغيل migrations وبذور البيانات واختبارات منع التكرار وسير المراجعة.
4. ربط Provider رسمي واحد على الأقل للأخبار والبريد والذكاء الاصطناعي، مع timeouts وretries وcircuit breaker.
5. تفعيل التحليلات والإعلانات فقط بعد موافقة ملفات الارتباط، واستبدال نطاق المثال بالنطاق الفعلي.
6. تنفيذ فحوص الوصول وLighthouse والبيانات المنظمة والضغط والنسخ الاحتياطي والاستعادة.

## ضوابط الأمن والتحرير

- منع النشر الآلي للسياسة والأمن والطب والقانون والحوادث والسمعة والشائعات.
- تنقية HTML، منع التنفيذ داخل المحتوى، قيود رفع الملفات، CSP وHSTS وsecure cookies.
- سجل غير قابل للتلاعب للقرارات الحساسة، والاحتفاظ بكل `ArticleVersion` وتصحيح.
- تنبيه عند فشل الجلب أو ارتفاع الرفض أو انخفاض درجة المصدر.

## الاستعداد للجوال

تظل API بلا اعتماد على واجهة الويب، وتستخدم معرفات وروابط عميقة ثابتة. بعد المصادقة تُنقل المحفوظات والتفضيلات من Local Storage إلى الحساب، ثم يضاف Service Worker للتخزين الجزئي وWeb Push. يمكن لتطبيق React Native أو Flutter استهلاك العقود نفسها.

## دليل المحرر المختصر

افتح المراجعات، تحقق من المصدر والتطابق والحساسية، اقرأ الملخص مقابل النص الأصلي، أضف السياق وسبب الأهمية، ثم اعتمد أو أرسل للتحقق. عند التعديل بعد النشر أنشئ نسخة جديدة وسجّل إن كان التغيير تحديثًا أم تصحيحًا.
